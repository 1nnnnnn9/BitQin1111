# 紧凑工程线框图

当用户提供白底细框、蓝色连线的流程图参考，或明确要求这种表现时，记录 `diagram_style: "engineering_wireframe"`。它是框图的局部处理方式，不改变整套 PPT 的配色选择，也不等于要求卡通、实物插画或把所有页改成方框。不另起一轮重复询问已明确的参考风格。

## 先排关系，再排框

- 主流程与支流程分别成行／泳道，合流处用简洁的直角连接或共享汇流干线。主支线的距离应能看清关系，避免把两条短线分散在页面上下两端。
- 框宽适应文字和换行：1280 像素画布上，短工序可从约 110–180 像素宽、52–72 像素高开始；长说明适当加宽。它们是排版起点，不是必须统一的尺寸。不要把每个短标签都塞进宽大的等尺寸色块。
- 标签优先用约 20–24 像素的深灰常规字重，居中并留边；主支路标题可加粗。实际渲染后按观看距离调整，不因装不下就缩成小字。
- 普通节点白色或近白色填充、灰色细边；箭头用清楚的蓝色，保持线宽、箭头和连接位置一致。只对关键工序加浅蓝填充和蓝色描边，避免整条流程全部铺浅青色。
- 外框必须有分组含义。单条追溯链不用再套一圈大框；多条并行处理线属于同一阶段时才加组框，并留出原生组标题位置。框、线和箭头仍由图片工具绘制。
- 图可以整体紧凑地居中，保留外部留白；不为了铺满画布拉长节点或留出巨大内部空洞。外部留白与失衡、稀疏的布局是不同问题。

## 规格与生成

根级 `diagram_style` 用作本稿框图默认值；页面的 `visual_plan.diagram_style` 可单独指定。只影响流程、关系、布局和工位类图解，原始照片、科研图表、封面配图保持原来的处理方式。

```json
"diagram_style": "engineering_wireframe",
"visual_plan": {
  "purpose":"process", "form":"flowchart",
  "explanation":"两条加工支线合流，关键处理阶段用单一浅蓝重点",
  "box":[60,210,1160,380],
  "nodes":[
    {"id":"a","box":[100,300,150,60]},
    {"id":"b","box":[320,300,150,60]}
  ],
  "relations":[{"from":"a","to":"b","kind":"rightward directed arrow"}],
  "highlight_nodes":["b"],
  "groups":[]
}
```

`highlight_nodes` 引用已有节点 ID；不选重点可为空。`groups` 仅用于真实分组，例如 `{"kind":"parallel_stage","box":[80,240,420,280],"members":["a","b"]}`，框体必须包住这些节点。组标题仍放在 texts 中，不写进图片。空 groups 表示不添加外围组框。

有用户图片参考时查看原图，把它作为样式参考输入图片工具，并登记来源；只学习布局、框线与重点，不抄入旧内容、旧数字或图内文字。图片生成后按实际框体校准标签。

不要为了得到“简图”批量替换全稿提示词、把所有节点都改成同一种大矩形；应保留页面语义、分支与分组。prepare_background_jobs.py 会把选定的工程框图合同加入任务，不需要绕过它另写无差别的空白母版提示词。

## 验收

选择实际问题页做验证；场地平面样页的批准不能代替工艺流程图的验证。检查：合流方向和并行关系、节点尺寸与字重、箭头一致性、单一重点、无多余外围框、标签与边线不相碰。仍要叠字后看图，不能仅因“节点数正确且图片无字”就通过美观检查。
