# 先决定用什么图解释

视觉质量以 codex-ppt 为基准。先按原风格规划一张完整、有层次的页面，再仅把涉及新增文字的位置留空；背景、分区、图解、箭头、图标和装饰可以是一体。文字叠加后应接近同风格整页图片版的完整度。留白不能成为削弱设计的理由，也不能把简略图偏好理解成全稿统一方框。

## 配图偏好与页面语义

模板／风格决定配色、字体、密度；配图偏好单独询问并记录为 schematic、realistic 或 mixed。不要从“蓝白”“工程风”推断用户希望三维设备图。

| 偏好 | 绘图表现 |
| --- | --- |
| schematic 简略示意图为主 | 平面、正投影或俯视，清晰轮廓、有限填色，不强调材质与阴影 |
| realistic 写实／三维图为主 | 外观有解释价值时使用写实或三维图；关系与流程仍需画清楚 |
| mixed 按内容混合 | 流程和关系采用简图，外观说明采用写实图，保持统一配色 |

页面先回答“观众需要理解什么”，再选形式：

| 内容 | 优先形式 | 要核对的内容 |
| --- | --- | --- |
| 先后、分流、反馈 | flowchart 流程／泳道图 | 方向、节点、分支与合流 |
| 场地、动线、相邻关系 | block_layout 平面块图 | 方位、通道、邻接、跨越关系 |
| 典型工位 | workstation 俯视示意 | 工件、设备、人员、操作与周转空间 |
| 系统与职责连接 | systems 架构／关系图 | 层级、接口、输入输出与反馈 |
| 数值比较 | 数据图或原图，必要时表格 | 数据、单位、尺度与图形比例一致 |
| 明细、计算、参考资料 | 原生表格／文字 | 原值、可读性与来源 |

这是选择依据，不是每页强制一种形式。确有必要偏离时在 visual_plan.exception_reason 说明内容原因，不能为了省事把解释性页面批量改成表格。装饰配图不能计为解释性图解。不要把固定案例题目、工艺或数值写成全局模板。

若用户的简图参考属于白底细框、蓝色连线的紧凑工程流程图，使用 engineering-flowcharts.md 的局部框图处理。简略程度与排版精致程度分开：不能仅删除插画、保留一排宽大的同色方框，就视为已经符合参考图。

## 图与文字共同规划

每页 visual_plan 记录目的、图形形式、解释内容、主要配图区域。关系图可用 relationship_brief 描述结构，交由图片模型完成视觉设计；需要精确对齐时再提供节点位置与连接，不强制每页套固定节点网格。节点用不含文字的内部 ID，标签引用 texts 中的原生对象。标签框标记 role=diagram_label，并放在节点框内部，给框线留边。图片模型只接收结构与视觉说明，不接收标签文字。

节点不必都是方框：用 shape 说明它代表工件、设施、区域、虚线范围还是抽象模块。工位图应保留有解释价值的支承、定位与操作空间等简化结构；不能把所有物理内容变成一组没有特征的矩形。需要把说明放在物体外侧时，不设置该节点的 text_object，另放原生 diagram_label。

正文、表格和用户原图窗口应位于主要生成图解区域之外；图示标签可以在内部。若空间不够，精简内容、分图或调整页面，不把主图缩成角落装饰。使用用户原图时标记 source_figure，保持原始图片与比例；不让模型重新想象科研结果。

图片模型的框体位置可能偏离目标坐标。生成后先查看实际框体，再叠放标签并渲染检查；不能只按预设坐标放字后直接通过。必要时在 visual_plan.resolved_node_boxes 中记录实际观察到的节点框（以原节点 ID 为键），把原生标签放入这些框内；该字段只影响组装校验，不改变已记录的绘图提示词。涉及关系错误、缺节点或无法留字时仍需用同一图片后端修复。

新绘制的数据图仍走图片后端，必须提供真实数据及来源，检查每个图形标记和比例；坐标、数值和图例在原生文字层添加。无法可靠还原数据时记录问题并改用原始图或原生表格，不交付失真的图形。

## 双样页与后半段质量

选一个常规内容页和一个中后段复杂图解页。不要用封面＋结束页验证全稿，也不要只挑最容易的一页。两页放在同一 PPTX，给各页预览，一次确认。若全稿没有复杂图解，则选择内容与布局有代表性的第二页；单页任务只做一页。

全稿完成后查看缩略图的视觉节奏，并逐页检查：是否出现连续的大表格、后半段图解是否退化、图片是否只起装饰作用。表格页本身不判失败，附录明细也无需硬加图。每页记录实际观察、问题及修复；不能仅靠“有一张图片”判断图解充分。
